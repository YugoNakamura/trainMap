# trainMap

## サーバとクライアントの処理の分担(案)12/17

![処理分担.drawio](処理分担.drawio.svg)

サーバ側が列車のダイヤ管理，運航による列車座標管理を行い，現在運航している列車の座標をクライアントに送る(Ajax?)

クライアントはOSMのマップと路線をハイライト表示するための路線座標を持つ(どちらも表示用)．サーバから列車座標を受け取り，地図上にプロットする．

### 上記方式の利点
* ユーザがクライアントの表示範囲を変更しても，クライアントは座標を元にプロットする列車を選択することが出来る．
* 列車が駅間を移動中にページを開いた際の処理が楽．(サーバは列車座標を送る宛先にクライアントを追加するだけでよい．クライアントは受け取った列車座標をプロットするだけで良い．)

## 運行情報の管理

サーバ内では列車オブジェクトと線路オブジェクトを持つ
### 列車オブジェクト
* 各列車ごとにインスタンスを持つ
* それぞれのインスタンスが何時にどの駅に止まるかの情報を持つ←列車時刻表のイメージ
* ダイヤに対する現在時刻から駅間の何割進んだか更新し続ける

### 線路オブジェクト
* 路線の一定区間(例:100m)ごとに，上り側の最寄り駅からの距離と座標リストを持つ
* 列車オブジェクトの現在位置の駅間に対する割合を元に，駅から現在位置までの距離を求め，それに最も違い座標をリストから返す
